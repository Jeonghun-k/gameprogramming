## 1. 커서 위치 제어

콘솔 화면에서 원하는 (x, y) 위치로 커서를 옮긴 뒤 출력하는 함수. 게임 화면을 그릴 때 기본이 됨.

```c
#include <windows.h>

void gotoxy(int x, int y)
{
    COORD pos = { x, y };   /* x: 가로(열), y: 세로(행), 0부터 시작 */
    SetConsoleCursorPosition(GetStdHandle(STD_OUTPUT_HANDLE), pos);
}
```

- `COORD`: `x`, `y` 두 멤버를 가진 구조체 (`<windows.h>`)
- `GetStdHandle(STD_OUTPUT_HANDLE)`: 현재 콘솔 출력 창의 핸들
- 한글이나 `■` 같은 전각 문자는 **가로 2칸**을 차지하므로 x 좌표를 2씩 늘려야 칸이 맞음

## 2. 화면 지우기

```c
#include <stdlib.h>

system("cls");      /* Windows */
/* system("clear");    Linux / macOS */
```

- `system()`: 운영체제 명령어를 실행하는 함수 (`<stdlib.h>`)
- 화면 전체를 지우고 커서를 (0, 0)으로 돌려놓음
- 게임 루프에서 매번 `cls`를 하면 화면이 깜빡임 → 바뀐 부분만 `gotoxy`로 덮어쓰는 방식이 더 좋음

### 2-1. scanf 복습

```c
int n;
char c;
char str[20];

scanf("%d", &n);     /* 변수의 주소(&)를 넘겨야 함 */
scanf("%c", &c);
scanf("%s", str);    /* 배열 이름이 곧 주소라서 & 없음 */
```

- 입력 형식: `%d`(정수), `%f`(float), `%lf`(double), `%c`(문자), `%s`(문자열, 공백 전까지)
- 반환값: 성공적으로 읽은 항목 수 (실패하면 0, 입력 끝이면 `EOF`)

#### 2-1-1. ⚠️ scanf의 버퍼 관련 오류

키보드 입력은 바로 변수로 가지 않고 **입력 버퍼**에 먼저 쌓였다가 `scanf`가 꺼내 감.
`5`를 치고 Enter를 누르면 버퍼에는 `5\n`이 들어감.

```c
scanf("%d", &n);   /* '5'만 가져가고 '\n'은 버퍼에 남음 */
scanf("%c", &c);   /* 남아 있던 '\n'을 바로 읽어버림 → 입력을 안 기다리고 넘어감 */
```

**해결 방법**

```c
/* 방법 1: %c 앞에 공백 → 공백·개행을 건너뜀 */
scanf(" %c", &c);

/* 방법 2: 버퍼에 남은 것을 개행까지 비우기 */
while (getchar() != '\n');
```

**또 다른 오류: 무한 루프**

```c
while (1) {
    if (scanf("%d", &n) == 1) break;
    printf("숫자를 입력하세요\n");
    /* 여기서 버퍼를 안 비우면 'a'가 계속 남아서 무한 반복 */
    while (getchar() != '\n');
}
```

- 숫자 자리에 문자를 넣으면 `scanf`가 실패하고 그 문자가 버퍼에 그대로 남음
- `fflush(stdin)`은 C 표준에서 동작이 정의되지 않음 (Visual Studio에서만 됐던 것) → 쓰지 않는 게 안전

**게임에서 scanf 대신 getch를 쓰는 이유**

`scanf`는 Enter를 눌러야 입력이 끝남 → 키를 누르는 즉시 반응해야 하는 게임에는 맞지 않음.

| 함수 | Enter 필요 | 화면 표시 | 헤더 |
|---|---|---|---|
| `scanf` | O | O | `<stdio.h>` |
| `getchar` | O | O | `<stdio.h>` |
| `getch` | X | X | `<conio.h>` |
| `getche` | X | O | `<conio.h>` |

## 3. 아스키 코드 / 스캔 코드

### 3-1. 아스키 코드 (ASCII) : 전 세계적으로 사용하는 코드

- 문자를 0~127 숫자로 정해 둔 **국제 표준 코드**
- C에서 `char`는 사실 정수라서 `'A'`와 `65`는 같은 값

| 문자 | 코드 | 문자 | 코드 |
|---|---|---|---|
| `'0'` | 48 | `'A'` | 65 |
| `'1'` | 49 | `'a'` | 97 |
| Enter (`'\r'`) | 13 | Esc | 27 |
| 공백 | 32 | 백스페이스 | 8 |

- 숫자 문자 → 정수: `'7' - '0'` = 7
- 대문자 ↔ 소문자: 차이가 32 (`'a' - 'A'`)
- `getch()`로 숫자 키 `1`을 누르면 정수 1이 아니라 **49**가 들어옴 → `code - '1'`로 0을 만들어 배열 인덱스로 사용

### 3-2. 스캔 코드 : 키보드로 입력

- 키보드의 **물리적인 키**마다 붙은 번호
- 문자가 없는 키(방향키, F1~F12, Home 등)를 구분할 때 사용
- `getch()`로 방향키를 누르면 값이 **두 번** 들어옴: 먼저 `224`(또는 `0`), 그다음 스캔 코드

| 키 | 스캔 코드 |
|---|---|
| ↑ | 72 |
| ↓ | 80 |
| ← | 75 |
| → | 77 |

```c
int key = getch();
if (key == 224 || key == 0)   /* 확장 키 신호 */
{
    key = getch();            /* 실제 스캔 코드 */
    switch (key)
    {
    case 72: /* 위 */     break;
    case 80: /* 아래 */   break;
    case 75: /* 왼쪽 */   break;
    case 77: /* 오른쪽 */ break;
    }
}
else if (key == 27)
{
    /* Esc */
}
```

## 4. 길이가 n인 표준 정사각형

`gotoxy`로 원하는 위치에 한 변이 n인 정사각형을 그리는 예.

```c
void draw_square(int x, int y, int n)
{
    int i, j;
    for (i = 0; i < n; i++)
    {
        gotoxy(x, y + i);           /* 줄마다 시작 위치로 이동 */
        for (j = 0; j < n; j++)
            printf("■");
    }
}
```

**테두리만 그리기**

```c
for (i = 0; i < n; i++)
{
    gotoxy(x, y + i);
    for (j = 0; j < n; j++)
    {
        if (i == 0 || i == n - 1 || j == 0 || j == n - 1)
            printf("■");
        else
            printf("  ");           /* 전각 문자에 맞춰 공백 2칸 */
    }
}
```

- 콘솔 글자는 세로가 가로보다 약 2배 길어서, 가로 2칸짜리 `■`를 써야 정사각형 비율에 가깝게 보임

## 5. 메뉴 만드는 코드

`do-while` + `switch` 조합이 기본 형태. 메뉴는 최소 한 번은 보여줘야 하므로 `do-while`이 잘 맞음.

```c
int menu_display(void)
{
    int select;
    system("cls");
    printf("===== 메뉴 =====\n");
    printf("1. 게임 시작\n");
    printf("2. 설명 보기\n");
    printf("0. 종료\n");
    printf("선택 > ");
    scanf("%d", &select);
    return select;
}

int main(void)
{
    int c;
    do
    {
        c = menu_display();
        switch (c)
        {
        case 1: /* 게임 시작 */ break;
        case 2: /* 설명 */      break;
        case 0: break;
        default: printf("잘못 입력했습니다.\n");
        }
    } while (c != 0);
    return 0;
}
```

- 메뉴 출력과 처리를 함수로 나누면 `main`이 깔끔해짐
- 숫자 대신 문자를 입력하면 2-1-1의 무한 루프가 생길 수 있음

## 6. 난수 만드는 코드

```c
#include <stdlib.h>   /* rand, srand */
#include <time.h>     /* time */

srand(time(NULL));                  /* 시드 초기화: 프로그램 시작 시 한 번만 */
int r = rand() % 10;                /* 0 ~ 9 */
int d = rand() % 6 + 1;             /* 1 ~ 6 (주사위) */
int k = rand() % (b - a + 1) + a;   /* a ~ b */
```

- `rand()`: 0 ~ `RAND_MAX`(Windows에서 32767) 사이 값
- `srand`를 안 하면 실행할 때마다 **같은 순서**의 난수가 나옴 (의사 난수)
- `time(NULL)`: 현재 시각(초) → 실행할 때마다 다른 시드
- `srand`를 반복문 안에서 계속 호출하면 같은 1초 안에서는 같은 값이 반복됨 → **한 번만** 호출

## 7. 가변인수

### 7-1. 일반 함수

함수를 만들 때 매개변수가 3개면, 호출할 때도 인수(argument)를 정확히 3개 넘겨야 함.

```c
int add3(int a, int b, int c);
add3(1, 2, 3);    /* O */
add3(1, 2);       /* X 컴파일 에러 */
```

### 7-2. 가변인수

인수 개수를 호출할 때마다 다르게 할 수 있게 만든 것. 대표적인 예가 `printf`.

```c
#include <stdarg.h>

int sum(int count, ...)        /* ... = 가변인수 */
{
    va_list ap;                /* 가변인수 목록을 가리킬 변수 */
    int i, total = 0;

    va_start(ap, count);       /* 마지막 고정 매개변수 다음부터 시작 */
    for (i = 0; i < count; i++)
        total += va_arg(ap, int);   /* 다음 인수를 int로 꺼냄 */
    va_end(ap);                /* 정리 */

    return total;
}

sum(3, 10, 20, 30);      /* 60 */
sum(5, 1, 2, 3, 4, 5);   /* 15 */
```

| 매크로 | 역할 |
|---|---|
| `va_list` | 가변인수 목록 포인터 타입 |
| `va_start(ap, 마지막고정인수)` | 목록 시작 |
| `va_arg(ap, 자료형)` | 다음 인수를 꺼냄 |
| `va_end(ap)` | 사용 종료 |

- 고정 매개변수가 **최소 1개** 있어야 함
- 함수는 인수가 몇 개인지 스스로 모름 → 개수를 첫 인수로 넘기거나(`count`), `printf`처럼 서식 문자열(`%d`의 개수)로 알려줘야 함

## 8. 배열이란?

**같은 자료형의 값들을 하나의 이름으로 묶어두고, 인덱스로 꺼내 쓸 수 있는 것.**

```c
int song[] = { SOL, SOL, LA, LA };
//  인덱스:     [0]  [1]  [2] [3]

song[0];   /* SOL */
song[3];   /* LA, 원소가 4개면 마지막 인덱스는 3 */

int n = sizeof(song) / sizeof(song[0]);   /* 원소 개수 = 전체 바이트 / 원소 하나 바이트 */
```

- 인덱스는 **0부터** 시작
- 메모리에 **연속으로** 붙어 있음 → `arr[i]`로 바로 접근 가능 (빠름, O(1))
- 범위를 벗어난 인덱스(`song[4]`)는 컴파일 에러 없이 엉뚱한 메모리를 읽음 → 버그 주의
- 반복문과 함께 `arr[i]`로 쓰는 경우가 대부분

## 9. 링크드 리스트란?

### 9-1. 각 칸이 자신의 값과 다음 값이 있는 곳을 가리키는 값, 두 가지를 같이 담고 있는 것

```
head → [ A | •]→[ K | •]→[ D | •]→[ B | •]→[ F | NULL ]
        데이터 링크
```

- 한 칸 = **노드(node)**
- **데이터 필드**: 실제 값
- **링크 필드**: 다음 노드의 주소
- **head**: 리스트의 시작 위치. 이것만 기억하면 전체를 따라갈 수 있음
- 마지막 노드의 링크는 `NULL` (끝 표시)
- 노드마다 링크가 하나인 것 = **단순 연결 리스트(singly linked list)**

**C로 표현: 자기 참조 구조체**

```c
struct linked_list {
    char data;
    struct linked_list *link;   /* 자기와 같은 구조체를 가리키는 포인터 */
};
```

**끝에 노드 추가**

```c
void add_node(char data)
{
    struct linked_list *new_node, *last;
    last = head;
    while (last->link != NULL)          /* 1. 마지막 노드 찾기 */
        last = last->link;
    new_node = (struct linked_list *)malloc(sizeof(struct linked_list));
    new_node->data = data;              /* 2. 새 노드 채우기 */
    new_node->link = last->link;        /*    (= NULL) */
    last->link = new_node;              /* 3. 마지막 노드에 연결 */
}
```

**순서대로 출력**

```c
void print_linked_list(struct linked_list *now)
{
    while (now != NULL)
    {
        printf("%c ", now->data);
        now = now->link;                /* 다음 노드로 이동 */
    }
}
```

**배열 vs 링크드 리스트**

| | 배열 | 링크드 리스트 |
|---|---|---|
| 메모리 배치 | 연속 | 흩어져 있음 (링크로 연결) |
| i번째 접근 | 바로 가능 O(1) | 처음부터 따라가야 함 O(n) |
| 중간 삽입/삭제 | 원소를 밀고 당겨야 함 O(n) | 링크만 바꾸면 됨 O(1) |
| 크기 | 고정 | 실행 중 자유롭게 변경 |
| 추가 메모리 | 없음 | 노드마다 링크 포인터 |

**게임에서의 활용: 리플레이**
버튼을 누를 때마다 노드를 만들어 순서대로 연결해 두면, 필요한 만큼만 메모리를 쓰고 head부터 따라가며 게임을 재연할 수 있음.

### 9-2. 트리, 그래프는 링크드 리스트로 구현해야 된다 → ❌ 아님

#### 9-2-1. 배열로도 구현 가능하다

- **트리**: 완전 이진 트리는 배열로 표현 가능
  - 인덱스 `i`의 부모 → 왼쪽 자식 `2i + 1`, 오른쪽 자식 `2i + 2`
  - 우선순위 큐에 쓰는 힙(heap) 자료구조는 보통 배열로 구현
- **그래프**: 인접 행렬(2차원 배열)로 표현 가능
  - `graph[i][j] = 1`이면 정점 i와 j가 연결됨

#### 9-2-2. 하지만 효율이 떨어질 수 있다

- 트리가 한쪽으로 치우치면 배열에 **빈칸이 많이 생겨 메모리 낭비**
- 노드를 자주 추가/삭제하면 배열은 원소를 옮겨야 해서 느림
- 정점은 많은데 연결이 적은 그래프는 인접 행렬이 대부분 0 → 낭비 (이럴 땐 인접 리스트 사용)
- 반대로 완전 이진 트리나 연결이 빽빽한 그래프는 **배열이 더 효율적**
- 결론: 어느 쪽이 무조건 맞는 게 아니라 **데이터 모양과 자주 하는 연산에 따라 선택**

## 10. 스택 다음 큐를 배운다

**스택 (Stack)**: 데이터의 추가와 삭제가 **한쪽(top)에서만** 일어나는 구조
→ 나중에 넣은 것이 먼저 나옴: **LIFO (Last In, First Out)**

```
 push ↓   ↑ pop
top  [D]
     [C]
     [B]
bottom [A]
```

- 예: 찜질방 수건 더미, 원카드 게임의 버린 카드 더미, Ctrl+Z
- `push`: 새 노드를 맨 위에 올림 / `pop`: 맨 위 노드를 꺼내고 `free`로 해제

```c
void push(char data)
{
    struct stack_node *new_node = (struct stack_node *)malloc(sizeof(struct stack_node));
    new_node->data = data;
    new_node->link = top;    /* 지금 맨 위를 가리키고 */
    top = new_node;          /* 새 노드가 맨 위가 됨 */
}

char pop(void)
{
    struct stack_node *temp = top;
    char data = top->data;
    top = top->link;         /* 한 칸 아래가 맨 위가 됨 */
    free(temp);              /* 메모리 반환 */
    return data;
}
```

**큐 (Queue)**: 한쪽(rear)으로 넣고 반대쪽(front)으로 꺼냄
→ 먼저 넣은 것이 먼저 나옴: **FIFO (First In, First Out)**

```
넣기 → [D][C][B][A] → 빼기
      rear        front
```

| | 스택 | 큐 |
|---|---|---|
| 방식 | LIFO (후입선출) | FIFO (선입선출) |
| 넣는 곳 / 빼는 곳 | 둘 다 top | 넣기 rear, 빼기 front |
| 예 | 수건 더미, 실행 취소 | 줄 서기, 프린터 대기열, 키 입력 버퍼 |

## 11. 배열의 문제점

배열을 사용할 때 가장 큰 문제는 **배열의 크기를 미리 정해야 한다는 것**.

- 미리 정한 크기보다 적게 사용하면 → **메모리 낭비**
- 미리 정한 크기보다 많이 필요하면 → **더 넣을 수 없음**
- 따라서 메모리를 효율적으로 쓰려면 **프로그램 실행에 필요한 만큼만** 기억 공간을 확보하는 방법이 필요

**해결 방법**
정보가 생성될 때마다 그 정보에 맞는 자료형으로 메모리에 저장하고, 정보가 필요 없어지면 다른 정보를 저장할 수 있도록 메모리 공간을 **돌려주는 것**.

- 이 방법을 **동적 메모리 관리(dynamic memory management)** 라고 함
- **동적 할당(dynamic allocation)**: `malloc`으로 메모리 확보
- **반환(deallocation)**: `free`로 메모리 돌려주기

```c
#include <stdlib.h>

int n;
scanf("%d", &n);                            /* 실행해 봐야 크기를 앎 */
int *p = (int *)malloc(sizeof(int) * n);    /* 필요한 만큼만 확보 */
if (p == NULL) { /* 할당 실패 처리 */ }

p[0] = 10;                                  /* 배열처럼 사용 */

free(p);                                    /* 다 쓰면 반환 */
p = NULL;                                   /* 해제한 주소를 다시 쓰지 않도록 */
```

- `malloc`은 **바이트 수**를 받고, 확보한 메모리의 **시작 주소**를 돌려줌 (실패하면 `NULL`)
- 반환형이 `void *`라서 원하는 포인터형으로 형변환해서 씀
- `free`를 안 하면 **메모리 누수(memory leak)**
- 링크드 리스트가 바로 이 방식: 노드가 필요할 때마다 `malloc`, 지울 때 `free`

## 12. 힙과 스택

> ⚠️ **필기 정정**: 필기 12-1, 12-2는 **반대로** 적혀 있음.
> - ~~힙은 런타임에 크기가 미리 결정됨~~ → **힙은 런타임(실행 중)에 크기가 결정됨**
> - ~~스택은 컴파일 타임에 동적으로 크기가 결정된다~~ → **스택은 컴파일 타임에 크기가 미리 결정됨**

### 12-1. 힙 (Heap) 영역

- **런타임(실행 중)** 에 필요한 만큼 크기가 결정됨
- `malloc`으로 확보하고 `free`로 **직접** 해제
- 크기가 크고, 상대적으로 느림

### 12-2. 스택 (Stack) 영역

- **컴파일 타임**에 크기가 미리 결정됨
- 지역 변수, 매개변수, 함수 호출 정보가 저장됨
- 함수가 시작될 때 생기고 끝나면 **자동으로** 사라짐
- 크기가 작고(보통 1MB 정도), 빠름

### 12-3. 변수는 스택에 만들어지고, 스택 안에 힙의 주소가 들어간다

### 12-4. 객체(동적으로 만든 데이터)는 힙 안에 만들어진다

```c
void func(void)
{
    int a = 10;                          /* a → 스택 */
    int *p = (int *)malloc(sizeof(int)); /* 포인터 변수 p → 스택
                                            p가 가리키는 int 공간 → 힙 */
    *p = 20;
    free(p);                             /* 힙은 직접 해제 */
}                                        /* 함수가 끝나면 a, p는 자동으로 사라짐 */
```

```
   스택                      힙
┌──────────┐
│ a = 10   │
├──────────┤            ┌──────────┐
│ p = 주소 ─┼──────────▶ │   20     │
└──────────┘            └──────────┘
```

> ⚠️ `free(p)`를 안 하고 함수가 끝나면, 스택의 `p`는 사라지지만 힙의 공간은 남음 → 주소를 잃어버려 다시는 해제할 수 없음 (메모리 누수)

### 12-5. 메모리 영역을 확보하는 함수 : malloc 함수

```c
void *malloc(size_t size);   /* <stdlib.h>, size 바이트만큼 힙에 확보 */
void free(void *ptr);        /* 확보했던 메모리 반환 */
```

### 12-6. 실행 중에 메모리를 사용해서 동적 메모리 할당이라고 한다

| | 정적 할당 (스택) | 동적 할당 (힙) |
|---|---|---|
| 크기 결정 | 컴파일 타임 | 런타임 |
| 방법 | `int arr[10];` | `malloc(sizeof(int) * n)` |
| 해제 | 자동 | `free`로 직접 |
| 크기 변경 | 불가 | 가능 (`realloc`) |

> 💡 **"스택"이라는 말이 두 번 나옴**: 12장의 **메모리 영역 스택**과 10장의 **자료구조 스택**은 다른 개념. 둘 다 "나중에 들어간 것이 먼저 나오는(LIFO)" 방식으로 동작해서 이름이 같음. 마찬가지로 12장의 **힙 영역**과 9-2의 **힙 자료구조**도 서로 다른 개념.
