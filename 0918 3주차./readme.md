## 1. C 컴파일 단위는 파일(번역 단위) 기준

- C 프로그램은 여러 개의 `.c` 소스 파일로 나눠 작성할 수 있고, 컴파일러는 **파일(translation unit) 단위**로 각각 컴파일한다.
  - 즉 `main.c`, `card.c` 처럼 파일을 나눠도 컴파일 자체는 파일마다 독립적으로 일어난다.
  - 컴파일이 끝나면 각 파일은 오브젝트 파일(`.o`/`.obj`)이 되고, **링커(linker)**가 이 오브젝트 파일들을 하나로 묶어 최종 실행 파일(`.exe`)을 만든다.
- 컴파일러는 지금 컴파일 중인 파일 **안에서만** 코드를 보기 때문에, 다른 파일에 정의된 함수를 쓰려면 그 함수의 **원형(prototype)**을 먼저 알려줘야 한다. (그래서 헤더 파일에 원형을 선언해두고 `#include`로 가져오는 것)
- 이번 강의자료 예제들에서 반복적으로 보이는 패턴도 이 개념과 이어진다:
  ```c
  void make_card(trump m_card[]);
  void display_card(trump m_card[]);
  void shuffle_card(trump m_card[]);

  int main(void)
  {
      trump card[52];
      make_card(card);
      shuffle_card(card);
      display_card(card);
      return 0;
  }

  void make_card(trump m_card[]) { ... }      // 실제 정의는 아래(또는 다른 파일)
  void display_card(trump m_card[]) { ... }
  void shuffle_card(trump m_card[]) { ... }
  ```
  - `main` 함수보다 먼저 각 함수의 **원형**을 선언해 두고, 실제 **정의**는 파일 뒤쪽(혹은 다른 파일)에 두는 구조.
  - 파일을 나눠 컴파일해도 컴파일러가 "이런 이름과 시그니처의 함수가 어딘가에 존재한다"는 걸 알 수 있게 해주는 역할.

## 2. 수식의 구성요소 — `variable = expression`

- 대입문의 기본 형태: `변수 = 수식;`
  - **좌변(lvalue)**: 값을 저장할 수 있는 변수(메모리 위치를 가리킴)
  - **우변(expression)**: 연산자와 피연산자의 조합으로 하나의 결과값을 만들어내는 식
- 강의자료 예제에서의 실제 사례:
  ```c
  rnd = rand() % 10;          // rand()%10 이 expression, rnd가 variable
  m_card[j].number = j % 13 + 1;
  temp = do_scale * pow(2, octave - 1);
  ```
  - `rand() % 10`처럼 함수 호출 + 연산자가 결합된 것도 expression 하나로 취급됨.
  - expression은 계산이 끝나면 하나의 값으로 평가(evaluate)되고, 그 값이 좌변 변수에 저장(대입)됨.

## 3. seed 값과 `srand(time(NULL))`을 쓰는 이유

**rand()**
- `0 ~ RAND_MAX` 사이의 정수를 반환하는 난수 생성 함수.
- 사실은 정해진 계산식으로 다음 값을 만들어내는 **"의사난수(pseudo-random)"**이며 완전한 무작위는 아니다.

**seed(씨앗값)**
- `rand()`가 다음 난수를 계산할 때 사용하는 **시작 기준값**.
- 같은 seed → 항상 같은 순서의 난수가 나온다 (규칙적, 재현 가능).
- seed를 따로 지정하지 않으면 기본값 `1`로 고정되어, 프로그램을 몇 번 실행하든 매번 똑같은 난수 순서가 나온다.

**srand(seed값)**
- `rand()`의 seed를 설정해주는 함수.
- 보통 `main()` 시작 부분에서 **딱 한 번만** 호출한다.

**왜 `time(NULL)`을 seed로 썼는가**
- `time(NULL)`은 현재 시각(초 단위)을 반환한다.
- 프로그램을 실행할 때마다 시각이 달라지므로 seed 값도 매번 달라진다 → 실행할 때마다 다른 난수 순서가 나오게 되어, 진짜 랜덤처럼 보이게 만드는 방법이다.

강의자료의 실제 사용 예:
```c
srand(time(NULL));
for (i = 1; i <= 10; i++)
    printf("%2d:%d\n", i, rand() % 6 + 1);   // 주사위 눈금 (1~6)

srand(time(NULL));
for (i = 1; i <= 6; i++)
    printf("%2d:%d\n", rand() % 45 + 1);     // 로또 번호 (1~45)
```

> **한 줄 요약**: `rand()`는 규칙적인 의사난수를 만드는데, 이 규칙의 시작점이 seed다. seed를 고정하면 항상 같은 난수가 나오니까, 매번 바뀌는 `time(NULL)`을 seed로 줘서 실행할 때마다 다른 난수가 나오게 만든 것이다.
>
> **추가 메모**: `srand`에 `time`을 쓰는 이유는, `rand()`만 쓰면 프로그램을 켤 때마다 같은 값들이 반복해서 나오게 되는데, `srand`로 시작값(seed)을 지정할 때 초 단위로 계속 바뀌는 `time(NULL)` 값을 넣어줌으로써 시작값을 계속 변화시키기 위해서다.

## 4. 카드 표시 — `order`, `shape`, `number`가 왜 `char`인가

강의자료의 구조체:
```c
struct trump
{
    char order;      // 카드의 우선순위 (모양 순위)
    char shape[3];    // 카드 모양 (2바이트 완성형 기호 + 널문자)
    char number;      // 카드의 숫자(또는 문자 A/J/Q/K)
};
trump card[52];
```

**`order`, `number`가 `char`인 이유**
- C에서 `char`는 1바이트 정수 타입이기도 해서, 작은 정수를 담는 용도로도 쓸 수 있다.
- `order`(0~3), `number`(카드 숫자/문자 코드) 모두 `char` 하나(1바이트)에 충분히 들어갈 정도로 값의 범위가 작다.
- 굳이 4바이트짜리 `int`를 쓰지 않고 `char`를 사용해서 메모리를 절약하려는 의도.
  - 카드가 52장이므로 구조체 하나하나의 크기를 줄이면 전체 메모리 사용량도 줄어든다.

**`shape[3]`이 왜 3바이트인가**
- ♠ ◆ ♥ ♣ 같은 확장 완성형 기호는 2바이트 문자다.
- 문자열의 끝을 표시하는 널 문자(`'\0'`)가 1바이트 추가로 필요하다.
- 2바이트(기호) + 1바이트(널 문자) = **3바이트**가 필요해서 `char shape[3]`으로 선언한 것.

## 5. 카드 섞기 / 카드 섞은 후 출력

카드 섞기는 카드의 위치를 서로 랜덤하게 교환하는 방식으로 구현된다(스와핑 기반 셔플):

```c
void shuffle_card(trump m_card[])
{
    int i, rnd;
    trump temp;
    srand(time(NULL));           // 난수의 초기화
    for (i = 0; i < 52; i++)
    {
        rnd = rand() % 52;
        temp = m_card[rnd];
        m_card[rnd] = m_card[i];
        m_card[i] = temp;
    }
}
```

- 0번 카드부터 51번 카드까지 순서대로 돌면서, 매 단계마다 `rand()%52`로 임의의 위치(`rnd`)를 하나 뽑아 현재 위치(`i`)의 카드와 서로 교환(swap)한다.
- 이 과정을 52번 반복하면 카드 전체가 섞인 상태가 된다.
- `srand(time(NULL))`을 함수 안에서 한 번 호출해 실행할 때마다 다른 셔플 결과가 나오도록 했다.

> **메모**: "srand, rand 사용 안 한다"고 적어뒀는데, 실제 슬라이드의 `shuffle_card` 코드는 `srand(time(NULL))`과 `rand()%52`를 그대로 사용해서 위치를 섞는 방식이다. 혹시 다른 셔플 방식(예: 정렬 알고리즘 기반)과 헷갈린 부분이 있다면 다음 시간에 슬라이드를 다시 확인해보면 좋을 것 같다.
